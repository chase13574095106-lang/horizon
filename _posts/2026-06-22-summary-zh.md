## [Claude Code 扩展思考输出为有损摘要](https://patrickmccanna.net/the-text-in-claude-codes-extended-thinking-output-is-not-authentic/) ⭐️ 8.0/10

开发者 Patrick McCanna 声称，Claude Code 的“扩展思考”输出是模型推理过程的有损摘要，而非真实的审计轨迹，引发了关于透明度和安全性的担忧。 这很重要，因为隐藏的推理过程可能掩盖提示注入攻击，使用户更难信任和优化 AI 模型，影响 AI 行业的安全性和竞争公平性。 该摘要被比作将无损 BMP 转换为有损 JPEG，导致数据丢失。隐藏推理还允许模型在隐藏阶段调用函数，可能泄露数据。

**背景**: 扩展思考是 Claude 模型的一项功能，允许模型在响应前逐步推理。然而，展示给用户的输出是压缩后的摘要，而非完整的推理链。这种做法在 OpenAI 和 Google 等主要 AI 公司中很常见，目的是保护专有推理技术。

## [Deno Desktop：用 Deno 构建桌面应用](https://docs.deno.com/runtime/desktop/) ⭐️ 8.0/10

Deno 推出了新的 `deno desktop` 命令，可将 Deno 项目编译为自包含的桌面应用程序，将代码、Deno 运行时和 Web 渲染引擎打包成每个平台一个二进制文件。 这使得开发者能够利用 Web 技术和 Deno 的安全模型构建跨平台桌面应用，提供多种后端（CEF、Webview、Raw）并计划共享 CEF 运行时以减小二进制体积，可能对 Electron 和 Tauri 构成挑战。 `deno desktop` 命令支持框架自动检测（Next.js、Astro、SvelteKit 等），并使用进程内绑定而非基于套接字的 IPC。共享 CEF 运行时已在路线图中，可将每个应用的二进制体积降至几 MB。

hackernews · GeneralMaximus · Jun 22, 05:38 · [社区讨论](https://news.ycombinator.com/item?id=48626137)

**背景**: Deno 是一个基于 V8 和 Rust 构建的现代 JavaScript 和 TypeScript 运行时，以其显式权限系统的安全优先方法而闻名。使用 Web 技术进行桌面应用开发传统上依赖于 Electron（捆绑 Chromium）或 Tauri（使用系统 webview），两者在二进制体积和性能上各有取舍。
