## [Language Models Can Rewrite Their Own Weights Without Gradients](https://arxiv.org/abs/2611.21885) ⭐️ 8.0/10

A new arXiv paper (2611.21885) claims that a language model can rewrite its own weights through reasoning alone, without gradients or training, and that over eight consecutive sessions its accuracy only rises. The model tests its edits on practice problems and submits only what works, each edit improving on the last. If validated, this approach could enable models to self-improve autonomously without expensive retraining, potentially accelerating AI capabilities. However, it also raises significant AI-safety concerns about models modifying their own safety-relevant weights and the blurring line between inference and training. The paper claims no gradients and no training, but the community notes that the only self-improvement observed was reducing reasoning trace length to avoid token limits, similar to prior weight-space programming work. The method involves iterative editing and testing, which some argue is a form of training by another name.

hackernews · lwhsiao · Nov 20, 16:29 · [Discussion](https://news.ycombinator.com/item?id=50577265)

**Background**: Traditionally, language models are trained via gradient descent, where backpropagation adjusts weights based on error. Weight editing refers to directly modifying a network's parameters without full retraining, and recent work like Google's Sleep framework and MIT CSAIL's weight-space programming has explored similar ideas. This paper pushes the concept further by having the model reason about its own weights.

## [OpenAI launches background mode: long tasks can run for 8 hours, tokens up to 40% cheaper](https://developers.openai.com/api/docs/guides/background) ⭐️ 8.0/10

OpenAI introduced a background mode for its API that executes long-running requests asynchronously by setting background: true and choosing a 2-hour or 8-hour completion window via background_options.completion_window, with token rates 30% and 40% lower than standard pricing respectively. The discount is currently in public beta on GPT-6.2 Astra, GPT-6.2 Sol, GPT-6.1 Terra, and GPT-6 Luna. This is a significant API capability change for developers running long tasks, as it removes timeout constraints and offers substantial cost savings for latency-tolerant workloads. However, the temporary storage of response data even when zero data retention is enabled raises important privacy and compliance considerations for regulated industries. If no completion window is set, the default 'soonest' option applies with no discount. Notably, background mode temporarily stores response data even when store is set to false or zero data retention is enabled, which is a caveat worth noting for privacy-sensitive applications.

telegram · zaihuapd · Nov 20, 11:15

**Background**: The standard Responses API call is synchronous: the app sends input, the model works, and the final output returns on the same connection, which can time out for long tasks. Background mode instead kicks off tasks asynchronously and lets developers poll response objects to check status over time. Zero Data Retention (ZDR) is an OpenAI option for eligible API customers that guarantees no logs are retained after a session ends, often used by enterprise and regulated customers.

## [KVM Flaw CVE-2026-99312 Lets Guests Read AMD Host Memory](https://thehackernews.com/2026/11/new-linux-kvm-flaw-cve-2026-99312-lets.html) ⭐️ 8.0/10

A Linux KVM vulnerability tracked as CVE-2026-99312 allows guest VMs on AMD hosts with nested virtualization enabled to read host memory; researchers demonstrated reading about 127 GB of host RAM from a guest on DigitalOcean. Upstream fixes shipped on November 18 in stable kernel 7.3.5 and related releases, but distribution kernels such as Debian and Ubuntu remain unpatched. This is a guest-to-host escape that breaks the core isolation guarantee of virtualization, and it is especially relevant to cloud providers that enable nested virtualization for developer sandboxes and CI/CD pipelines on AMD hardware. Until distro kernels catch up, many production hosts remain exposed even though an upstream patch exists. The flaw only affects hosts with AMD processors and nested virtualization enabled, and many cloud providers surveyed were not vulnerable because they do not enable nested virtualization on AMD. The practical mitigation until patched is to disable nested virtualization, and the bug appears rooted in a previous security fix.

telegram · zaihuapd · Nov 20, 14:23

**Background**: KVM is the hypervisor built into the Linux kernel and is the foundation of most public and private cloud VM infrastructure. Nested virtualization lets a guest VM itself run a hypervisor and launch its own VMs, which is useful for sandboxes and CI but widens the attack surface. A guest-to-host escape means code inside a VM can reach memory it should never see, potentially exposing other tenants' data.
